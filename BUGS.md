# Что было не так в Python-версии — и что с этим сделано

Разбирал проект файл за файлом. Ниже — найденное, с цитатами из кода.
Каждый пункт помечен: **✔ исправлено** — поправил прямо в Python, чтобы
старая версия работала; **→ Rust** — в новой версии этой ошибки нет
по построению.

> **Важно:** Python-версия из проекта удалена — осталась только Rust.
> Этот файл сохранён как запись разбора: он объясняет, почему в
> `capri-rs` что-то сделано именно так. Имена файлов вида `voice.py`
> относятся к удалённой версии.

---

## Серьёзное — ломает работу или теряет данные

### 1. Покупка скина не срабатывает ✔ исправлено, → Rust

`shop_dialog.py:125` кладёт купленный скин в список, но **не делает его
надетым**:

```python
def buy_skin(self, skin_id, price):
    if self.data["money"] >= price:
        self.data["money"] -= price
        self.data["owned_skins"].append(skin_id)
        SaveManager.save(self.data)
```

А `setup_ui()` (`shop_dialog.py:141`) после перерисовки заново читает данные
с диска и называет скин «куплен». Внешний вид Капри при этом не меняется —
`equipped_skin` остаётся прежним. Пользователь заплатил и не увидел ничего.

Как это выглядело: в `save_data.json` было `owned_skins: ["purple",
"neon", "neon"]` — «neon» дважды, а надет всё равно «purple». Покупка
записывалась, надевание — нет.

Стало: `buy_skin()` ставит `equipped_skin`, не плодит дубли и сразу шлёт
`update_avatar_skin`, а `SaveManager.load()` вычищает уже накопившиеся дубли.
В Rust-версии покупка и надевание — одно действие `SelectSkin`.

### 2. Прогресс теряется, если запускать не из папки проекта

`save_manager.py:4`:

```python
SAVE_FILE = "save_data.json"
```

Путь относительный, то есть ищется в **текущем каталоге**, а не рядом с
программой. `main.py` при этом `os.chdir()` не делает. Запуск из ярлыка,
из другой папки или через автозагрузку — и Капри читает чужой (или
несуществующий) файл, затирая прогресс значениями по умолчанию.

`config.json` при этом читается правильно — через
`os.path.join(BASE, "config.json")`. То есть несогласованность в самом
проекте.

Стало: `SAVE_FILE = os.path.join(BASE, "save_data.json")`, где `BASE` —
папка `save_manager.py`. Запись идёт через временный файл и `os.replace`,
чтобы обрыв питания не оставил половину JSON. В Rust-версии оба файла тоже
всегда берутся от каталога программы.

### 3. `tts_engine: "silero"` — движка не существует ✔ исправлено, → Rust

В `config.json` стоит `"tts_engine": "silero"`. `voice.py:452` читает это
значение:

```python
self.engine = cfg.get("tts_engine", "edge")
```

…и **нигде его не использует по назначению**. Единственное место —
`voice.py:534`, где оно попадает в ключ кэша. Ветки «а если sapi, то не
ходить в сеть» нет: `say()` (строки 470+) всегда идёт в edge-tts и только
при исключении падает на SAPI. Слово «silero» в коде не встречается
вообще (`grep silero voice.py` пуст).

Проверка: `python -c "import json;print(json.load(open('config.json',encoding='utf-8-sig'))['tts_engine'])"`
→ `silero`.

Последствие: пользователь думает, что выбрал другой движок, а получает
непонятную смесь. Плюс мусорное значение попадает в ключ кэша.

Стало: неизвестное значение даёт предупреждение в лог и заменяется на
`edge`, а `say()` при `tts_engine = "sapi"` действительно идёт мимо сети —
прямо в голос Windows. В Rust-версии движок — перечисление `edge`/`sapi`,
и мусорное значение так же честно попадает в лог.

### 4. Громкость голоса стоит на нуле ✔ исправлено, → Rust

`config.json`: `"voice_volume": 0`. При этом в `main.py:95` значение по
умолчанию — `100`. То есть ноль попал туда не из программы.

Итог: `voice.py` вызывает `play_mp3(path, self.stop_event, self.volume)` с
`volume=0` — файл играет в полной тишине. Из-за этого лог полон строк
«edge-tts недоступен», хотя настоящая причина — не сеть, а громкость:
`voice.say()` возвращает `False`, и вызывающий код считает, что синтез
не удался.

Отдельно путает кэш: громкость входит в ключ (`voice.py:534`), поэтому
смена громкости обнуляет весь кэш озвучки.

Стало: `Speaker.__init__` видит `volume <= 0`, пишет предупреждение и
говорит на 100. Ручная правка слайдером по-прежнему уважается: если человек
сам уводит громкость в ноль, Капри замолкает. В Rust-версии — то же
поведение.

### 5. Три библиотеки не установятся через `setup.bat`

`main.py:60-74` импортирует всё внутри одного `try/except ImportError`,
включая:

```python
from discord_rpc import DiscordRPC   # нужен pypresence
from chess_game import ChessGame     # нужен python-chess
```

А `requirements.txt` не содержит ни `pypresence`, ни `chess`, ни
`pynput` (его просит `discord_rpc.py`). `speech_recognition` и
`imageio-ffmpeg` в requirements есть, но при этом сами нигде, кроме
`voice.py`, не используются — зато они тянут за собой лишние зависимости.

Что видит пользователь: после `setup.bat` при запуске выскакивает окно
«Не установлены нужные библиотеки (pypresence)» с советом запустить
`setup.bat` — который эту библиотеку и не поставит. Замкнутый круг.

Стало: `requirements.txt` дополнен `pypresence`, `pynput` и `chess`.
В Rust-версии таких зависимостей нет вовсе: Discord RPC, шахматы и Spotify
в неё не переносились — они и в Python-версии держались на необъявленных
пакетах.

### 5а. `setup.bat` не умеет ставить пакеты из requirements ✔ проверено

За установку отвечает `tools\install.py`. Отдельной ошибки там нет —
достаточно, что список пакетов был неполным (пункт 5). После правки
`requirements.txt` установка ставит всё нужное.

### 6. Любое исключение в разборе команды — тишина ✔ исправлено, → Rust

`actions.py:1045` было:

```python
if self.pending:
    action, self.pending = self.pending, None
```

`pending` сбрасывался **до** вызова `action()`. Если `action()` бросал
исключение (например, `subprocess.Popen(["shutdown", ...])` не смог
запуститься), намерение терялось, а пользователь не узнавал, что
подтверждение вообще было принято.

Стало: сброс — только после успеха, а исключение ловится и превращается в
реплику Капри по ключу `error` («Сбой. Даже у меня бывают плохие дни: …»)
вместо тишины.

Остальные `except → pass` по проекту (20+) я не трогал: они вокруг
необязательных мелочей вроде записи звука, и переписывать их — значит
рисковать рабочей версией ради косметики. В Rust-версии такого нет:
ошибки возвращаются как `Result<_, String>` с русским текстом.

## Косметика и неудобства

### 7. Первый запуск отдаёт наружу сам `DEFAULT_DATA` ✔ исправлено, → Rust

`save_manager.py:20-24`:

```python
@staticmethod
def load():
    if not os.path.exists(SAVE_FILE):
        SaveManager.save(DEFAULT_DATA)
        return DEFAULT_DATA
```

Возвращается **сам** объект `DEFAULT_DATA`, а не его копия. Вызывающий код
его тут же меняет — `shop_dialog.py:125` делает
`self.data["owned_skins"].append(skin_id)`, `main.py` начисляет деньги и
опыт.

Воспроизводится так (в пустой папке, без `save_data.json`):

```
load() вернул тот же объект, что DEFAULT_DATA: True
DEFAULT_DATA после покупки: money = 228 skins = ['purple', 'neon']
```

То есть эталонные значения внутри модуля испорчены до конца работы
программы. Пока файл на диске есть, ошибка не видна — но стоит
`save_data.json` потеряться или оказаться нечитаемым (`load()` при
исключении тоже возвращал `DEFAULT_DATA`), как стартовые деньги и скины
приезжают уже изменёнными.

Стало: `SaveManager.default()` отдаёт `copy.deepcopy(DEFAULT_DATA)`;
проверено — после «покупки» эталон остаётся `money = 328`,
`owned_skins = ['purple']`. Заодно `load()` дополняет недостающие поля и
переживает битый JSON. В Rust-версии `SaveManager::load()` тоже всегда
собирает новую структуру.

### 8. Сон в потоках вместо таймеров → Rust

`main.py:687`:

```python
self.roam.emit()
time.sleep(1.5)
```

Это блокирует поток. Всего `time.sleep` по проекту 62 (`actions.py` — 24,
`automation.py` — 21, `main.py` — 7, остальное в `media.py`, `voice.py`,
`discord_rpc.py`). При выходе из программы часть этих потоков продолжает
спать, и завершение растягивается.

В Python-версии трогать не стал: переписывать все ожидания на таймеры — это
переделка всей архитектуры, а не исправление ошибки. В Rust-версии ожиданий
в потоках нет: окно живёт на `WM_TIMER` с шагом 40 мс, а состояние
передаётся через атомики и каналы.

### 9. `voice.py` импортирует то, чего не требует

`imageio_ffmpeg` и `speech_recognition` импортируются в `voice.py`, но
`speech_recognition` используется только как запасной путь, а
`imageio_ffmpeg` — для поиска ffmpeg. Оба пакета весят немало (ffmpeg
внутри — около 80 МБ) и в `requirements.txt` заявлены как обязательные.

Оставил как есть: оба действительно используются, просто не как основные.
В Rust-версии ffmpeg и SpeechRecognition не нужны совсем — распознавание
идёт через Vosk напрямую, а MP3 декодирует `rodio`.

### 10. Мёртвое значение `barge_in` при выключенном слухе → Rust

`barge_in` в `config.json` — `true`, но если Vosk не загрузился,
перебивание не работает, и в интерфейсе об этом ничего не сказано. Лог
пишет только «Слух недоступен».

В Rust-версии при недоступном слухе Капри прямо говорит фразу из
`persona` («Я тебя не слышу…»), а не молчит с включённой настройкой.

## Что проверено и в порядке

Чтобы не создавать ложного впечатления, что «всё плохо»:

- **Кодировки исходников.** Все `.py` — корректный UTF-8, `config.json`
  читается как UTF-8 без кракозябр (`sites`, `apps`, `wake_words` — живые
  русские слова). Логи `main.py` тоже пишутся в UTF-8 (`encoding="utf-8"`
  в `basicConfig`) — если открыть `capri.log` в старой программе, где
  кодировка не указана, кириллица покажется «РєР°РїСЂРё». Это проблема
  просмотрщика, а не файла.
- **Синтаксис.** `py_compile` всех 21 файла — без ошибок.
- **Неопределённые имена.** Статический разбор всех модулей не нашёл ни
  одного обращения к несуществующему имени (кроме `__file__`, которое
  подставляет сам Python).
- **`pending`-подтверждение выключения.** Плейсхолдеры совпадают:
  `persona.py` ждёт `{what}` и `{what_cap}`, `actions.py:1567` их передаёт;
  для `{what_noun}` — то же самое. Тут всё согласовано.
- **Слияние настроек.** `load()` подмешивает `DEFAULTS` поверх файла, так
  что отсутствующие ключи не роняют программу.
- **Кэш озвучки.** Ограничение в 600 файлов и 160 символов работает.

## Итог по правкам, которые были сделаны в Python-версии

Тронуто пять файлов, всё проверено `py_compile` и прогонами. Сами файлы
удалены вместе с версией — список остаётся как запись, что именно чинилось:

| Файл | Что изменено |
|---|---|
| `save_manager.py` | абсолютный путь к `save_data.json`, копия дефолта, атомарная запись, чистка дублей скинов |
| `shop_dialog.py` | покупка сразу надевает скин и перекрашивает Капри |
| `voice.py` | `tts_engine` наконец учитывается, `voice_volume <= 0` → 100 |
| `actions.py` | подтверждённое действие не теряется при ошибке |
| `requirements.txt` | добавлены `pypresence`, `pynput`, `chess` |

Не тронуто намеренно: `config.json`, `save_data.json` (это данные
пользователя), `main.py`, `avatar.py` и остальные диалоги — правок, которые
что-то реально ломают, там не нашлось, а переписывать рабочее ради стиля
смысла нет.

## Чем Rust-версия отличается по этим пунктам

| Проблема | Как в `capri-rs` |
|---|---|
| покупка без надевания | одно действие `SelectSkin` |
| путь к прогрессу | всегда от каталога программы |
| `tts_engine: "silero"` | тип-перечисление, мусор → лог + `edge` |
| `voice_volume: 0` | трактуется как 100 + предупреждение в лог |
| необъявленные зависимости | нет Python — нечего объявлять |
| проглоченные исключения | `Result<_, String>` с русским текстом |
| горячие регулярки | скомпилированы один раз (`Lazy<Regex>`) |
| сон в потоках | таймер окна (`WM_TIMER`, 40 мс) + атомики |
| падение при ошибке | `capri.log` + фраза от Капри, программа живёт |

Подробности запуска — в `capri-rs\README.md`.
