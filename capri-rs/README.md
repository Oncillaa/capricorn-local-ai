# capri-rs — исходники Капри 2.0

Рабочая папка Rust-версии. Пользовательская инструкция (запуск, Vosk,
настройки) — в `..\README.md` в корне проекта.

## Сборка

Нужен Rust 1.80+ (<https://rustup.rs>).

```bat
cargo build --release
```

Готовый файл — `target\release\capri.exe`. Его нужно положить рядом с
`config.json`, `assets\` и `models\`, то есть в корень проекта: exe ищет
настройки и рядом с собой, и в папках выше (до пяти уровней), поэтому из
`target\release\` он тоже всё находит — но держать его в корне удобнее.

## Тесты

```bat
cargo test --workspace
```

64 теста, все зелёные. Проверяется разбор команд, настройки, персона,
распознавание текста, звуковые утилиты и даты.

## Как устроено

```
crates/
├── core/    настройки, персона, разбор команд, индекс программ, нейросеть
├── win/     всё, что обращается к Windows
├── voice/   микрофон, распознавание, синтез, воспроизведение
├── ui/      окно аватара, подпись, меню в трее
└── app/     связка всего этого, точка входа
```

`core` не знает про Windows: любая системная возможность описана методом
типажа `capri_core::platform::Platform`, у которого по умолчанию возвращается
понятная ошибка. Поэтому разбор команд можно проверять тестами без запуска
программы, а `win` — единственное место, где вызывается Win32.

Потоки: окно живёт в главном потоке (Windows требует, чтобы окно создавалось
и жило в одном потоке), ядро — в рабочем. Общение — через каналы
`UiEvent`/`UiRequest` и атомики. Никаких `sleep` в горячем пути: анимация
идёт по таймеру окна с шагом 40 мс.

## Мелочи, которые стоит знать при правках

- **Vosk подгружается динамически** через `libloading`. Ищется
  `libvosk.dll` рядом с exe, в `exe\vosk\`, в текущем каталоге и в `PATH`.
  Нет библиотеки или модели — Капри работает без слуха, а не падает.
- **Edge TTS** — свой WebSocket-клиент (`voice/src/edge.rs`). Сервис требует
  заголовок `Sec-MS-GEC`: SHA-256 от «тиков» времени и открытого токена
  клиента, округлённых вниз до пяти минут. Без него сервер отвечает 403.
- **Голос Windows** — SAPI через COM, класс `SpVoice`
  (`{96749377-3391-11D2-9EE3-00C04F797396}`). Речь прерывается
  `SPF_PURGEBEFORESPEAK` с пустой строкой.
- **Окно аватара** — слоистое (`UpdateLayeredWindow`), рисуется вручную:
  `ui/src/canvas.rs` (пиксели и наложение), `ui/src/text.rs` (текст через
  GDI), `ui/src/sprite.rs` (кадры из `assets/`).
- **Горячие регулярные выражения** вынесены в `Lazy<Regex>`: они
  компилируются один раз, а не на каждую фразу.
- **Мьютекс `STATE` нельзя держать, пока открыто меню.** `TrackPopupMenu`
  не возвращает управление: он крутит свой цикл сообщений и внутри вызывает
  наш же `wndproc`, где приходит `WM_TIMER` и `tick()` снова берёт `STATE`.
  Это классическая самоблокировка потока — программа замирает намертво.
  Поэтому `show_menu()` получает только `hwnd` и клон канала команд, а
  `MenuGuard` не даёт открыть второе меню поверх первого.
- **Меню нужно отдать фокус.** Окно Капри создаётся с `WS_EX_NOACTIVATE`,
  иначе она отбирала бы активность у рабочего окна. Но неактивное окно не
  может держать всплывающее меню: оно не получает ни `Esc`, ни клика мимо.
  На время меню флаг снимается, окно активируется через `AttachThreadInput`
  (обычный `SetForegroundWindow` из фонового процесса Windows игнорирует),
  а после закрытия стиль и фокус возвращаются как были.
- **Клик и перетаскивание различаются по сдвигу мыши** (`DRAG_THRESHOLD`,
  4 пикселя), а не по факту нажатия: `WM_LBUTTONDOWN` всегда взводит
  `dragging`, поэтому проверять надо именно смещение.
- **Ошибки не роняют программу**: наверх идёт `Result<_, String>` с русским
  текстом, в лог — строка, пользователю — фраза из `persona`.

## Соглашения

- Всё, что видит и слышит пользователь (реплики, логи, сообщения об
  ошибках), — по-русски и в характере Капри. Идентификаторы — английские.
- В рантайме нет `unwrap()`, `expect()` и `panic!`: сбой возвращается как
  `Err(String)`. В тестах и при сборке статических регулярок — можно.
- `config.json` и `save_data.json` читаются из каталога программы, а не из
  текущего каталога: прогресс не должен зависеть от того, откуда запустили.
